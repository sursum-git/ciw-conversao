# Container fiscal readonly — plano e contrato

**Meta:** consultas nativas op1033/op1034 sobre memórias persistidas, com container MED obrigatório.
**Arquitetura:** um wrapper fixo `ContainerFiscalReadOnlyApi.p` e um serviço `ContainerFiscalReadOnlyService.p` para dois recursos. O leitor `CiwErpReadService.p` permanece responsável por filtros, ordenação e página. Alterações compartilhadas são patches com baseline SHA256.
**Tecnologia:** ABL 12.2 (gate oficial posterior), PHP existente e metadados JSON do construtor.

- [x] Testar contrato isolado com TT sem bancos: contexto, ownership, NULL, alias get estrito, página200 e ausência de writers; guards50mil/10s revisados, seleção única impede coletar50mil resultados.
- [x] Implementar API/serviço sem cálculos nem persistência; propor ramos fechados de reader/dispatcher/PHP.
- [x] Preparar duas entidades readonly, source additions e patch de navegação de despesas preservando abas/Logs.
- [x] Executar testes locais e revisão própria; emitir manifesto e gates para integração central.

Origem: `cons_calcs_imp_container` seleciona `dt_hr_calculo,desc_memoria_calc,calc_imp_container_id` com PK `calc_corrente`; `cons_despesas_container_memoria_calculo` seleciona `memoria_calculo` por `despesa_container_corrente`. O grid de despesas 3970–4000 abre cálculo quando PK não zero e sobrescreve pelo texto próprio quando não vazio. Ambas consultas exigem container e a PK selecionada em `contextFields`/`requestContextFields`. `read` e `get` restringem o buffer pela PK E pelo container MED. Não há writer ativo nessas consultas. Bibliotecas genéricas copiadas pelo Scriptcase não são eventos de tela.

Reuso suficiente parcial: `ContainersPainelReadService.p` já entrega memória no DTO de despesas; não tem histórico fiscal nem paginação/filtros ERP. A nova projeção lê os mesmos campos físicos; não replica regra/fórmula.

`calcs_imp_container.memoria_calculo` é INTEGER no dicionário; o texto fiscal é `desc_memoria_calc`. `dt_hr_calculo` será preservado em ISO DATETIME sem timezone como string; campo adicional `data_calculo` DATE permite filtro de período nativo sem inventar timezone. NULL permanece NULL em ambos. MED corresponde ao prefixo de `pp-container.cod-estabel = '5'`, como leitores container existentes.

Navegação: despesas existentes recebem link contextual para op1034; memória própria não vazia (inclusive espaços, sem TRIM) prevalece e faz `link_calculo_id=NULL`. Memória vazia/NULL permite link para op1033 pelo cálculo persistido positivo. Sem cálculo ou referência órfã não há cálculo inventado; leitura do órfão retorna404. Extensão readonly declarada: o link intermediário da despesa também aparece quando tudo está vazio, pois rowLinks nativos não possuem condição; não alegar paridade visual literal. A proposta inicial de histórico global/aba foi removida após revisãoP1: parâmetros não declarados eram ignorados pelo frontend. Prova RED→GREEN usa os métodos reais `CrudEngine.initializeNavigationContext` e `withContextFilters`.

Limites: página máxima200, `skip`0..100000 e filtros/ordenação do leitor existente. Coleta interrompe acima50mil ou10s e possui STOP-AFTER10, sem resultado parcial. Como a seleção exige PK única, a cardinalidade normal é0/1; o teste com51mil linhas alheias prova que não se amplia a consulta. Não alegar execução de50mil resultados ou teste de timeout de relógio. Ausência do registro selecionado404; parâmetros/alias inválidos422; writer405.
